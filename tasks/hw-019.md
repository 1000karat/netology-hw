### Задание 1
#### 🔧 Решение
1. Перейдите в каталог src. Скачайте все необходимые зависимости, использованные в проекте.
```shell script
$ terraform init
```
📌 Скриншот:
![Скриншот](https://raw.githubusercontent.com/1000karat/netology-hw/refs/heads/main/img/hw-019-02.png)

2. Изучите файл .gitignore. В каком terraform-файле, согласно этому .gitignore, допустимо сохранить личную, секретную информацию?(логины,пароли,ключи,токены итд)  
`personal.auto.tfvars` - cпециально помечен как хранилище личных переменных и исключён из Git.

3. Выполните код проекта. Найдите в state-файле секретное содержимое созданного ресурса random_password, пришлите в качестве ответа конкретный ключ и его значение.
```shell script
$ terraform apply
$ cat terraform.tfstate | grep result
```
📌 Скриншот:
![Скриншот](https://raw.githubusercontent.com/1000karat/netology-hw/refs/heads/main/img/hw-019-03.png)

4. Выполните команду ```terraform validate```. Объясните, в чём заключаются намеренно допущенные ошибки. Исправьте их.  

Error: Missing name for resource - Для ресурса нужно указывать тип и имя. В конце подсказка: All resource blocks must have 2 labels (type, name).    
Error: Invalid resource name - не верное имя ресурса. Ресурс должен называться с буквы или подчёркивания.  
Reference to undeclared resource - нету описанного ресурса для [random_password.random_string_FAKE.resulT](https://registry.terraform.io/providers/hashicorp/random/latest/docs/resources/password).  

5. Выполните код. В качестве ответа приложите: исправленный фрагмент кода и вывод команды docker ps.  
📌 Скриншот:
![Скриншот](https://raw.githubusercontent.com/1000karat/netology-hw/refs/heads/main/img/hw-019-04.png)

6. Замените имя docker-контейнера в блоке кода на ```hello_world```.  

`terraform plan` показывает красным что будет изменено. `terraform apply -auto-approve` выполняет все действия без дополнительной проверки человеком. Можно случайно: 
- удалить существующие ресурсы;
- пересоздать рабочие контейнеры;
- изменить сетевые настройки;
- удалить данные или инфраструктуру в облаке.

7. Уничтожьте созданные ресурсы с помощью terraform.
```shell script
$ terraform destroy -auto-approve
$ terraform state list
$ docker ps
```
