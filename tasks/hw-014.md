### Задание 1  
На лекции рассматривались режимы репликации master-slave, master-master, опишите их различия.

*Ответить в свободной форме.*

#### 🔧 Решение
Режимы репликации master-slave и master-master используются в базах данных для повышения отказоустойчивости, распределения нагрузки и сохранности данных.
В схеме master-slave существует один основной сервер (master) и один или несколько подчинённых серверов (slave).
Главная особенность заключается в том, что запись данных выполняется только на master-сервере, а slave-серверы получают копии изменений автоматически через репликацию.
**Master-Slave** удобен, когда:
- нужно разгрузить основной сервер за счёт распределения запросов на чтение;
- требуется резервная копия базы данных;
- важна простота настройки и администрирования.

 
Преимущества:
- простая архитектура;
- снижение нагрузки на master при большом количестве запросов на чтение;
- удобство резервирования данных.


Недостатки:
- master является единой точкой отказа;
- при выходе master из строя запись данных становится невозможной, пока не будет назначен новый master;
- возможны задержки репликации между master и slave.

В режиме **Master-Master** оба сервера являются основными и могут одновременно принимать операции записи и чтения.
Каждый сервер реплицирует изменения другому. Такая схема используется, когда:
- необходима высокая отказоустойчивость;
- требуется непрерывная работа системы;
- важно распределение нагрузки не только на чтение, но и на запись.  

Преимущества:
- отсутствие единственной точки отказа;
- оба сервера активны;
- можно распределять нагрузку между несколькими узлами.


Недостатки:
- более сложная настройка;
- возможны конфликты данных, если одинаковые записи изменяются одновременно на разных серверах;
- требуется механизм разрешения конфликтов и синхронизации.

### Задание 2
Выполните конфигурацию master-slave репликации, примером можно пользоваться из лекции.

*Приложите скриншоты конфигурации, выполнения работы: состояния и режимы работы серверов.*

#### 🔧 Решение
Для решения использовался [docker compose](https://github.com/1000karat/netology-hw/blob/main/files/hw-014/ms/docker-compose.yml) с версией mysql 8.0.46. С внешними файлами конфигурации и SQL создания пользователя.
1. Запуск
```shell script
$ docker compose up -d
```
2. Подключение к **Master**
```shell script
docker exec -it mysql-master mysql -uroot -ppassword
```
3. Получение значения `Position`.
```sql
SHOW MASTER STATUS;
```
4. Подключение к **Slave**
```shell script
docker exec -it mysql-slave mysql -uroot -ppassword
```
5. Настройка репликации. Заполнить значения для `SOURCE_LOG_FILE` и `SOURCE_LOG_POS` данными из п.3.
```sql
CHANGE REPLICATION SOURCE TO
    SOURCE_HOST='mysql-master',
    SOURCE_USER='repl',
    SOURCE_PASSWORD='replpassword',
    SOURCE_LOG_FILE='mysql-bin.000003',
    SOURCE_LOG_POS=157;

START REPLICA;
```
6. Проверка статуса на `Slave`:
```sql
SHOW REPLICA STATUS\G
```
Важно, чтобы были `Replica_IO_Running` и `Replica_SQL_Running` = `Yes`.
